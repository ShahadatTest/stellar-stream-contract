CLI

TypeScript executed directly by Node 22.6+. No build step, one dependency.

Commands

CommandPurpose
scanForecast archival for targets; human or --json output
verifySame data, exit 2 when something is critical or archived
registry listPrint the on-chain watchlist
registry add / removeMaintain your own entries (needs SENTINEL_SECRET)
doctorRPC health, ledger, protocol, network config

scan

sentinel scan [--contract C...]... [--config path] [--registry C...]
              [--network testnet|futurenet|mainnet] [--rpc-url url]
              [--warn-ledgers n] [--json]

Targets come from, in order: repeated --contract flags, a config file's contracts[], or the on-chain watchlist.

verify

ExitMeaning
0Nothing is CRITICAL or ARCHIVED
2Something is critical or archived (with --strict: also watch/urgent)
1The command failed

registry

sentinel registry list [--all] [--json]
sentinel registry add --target CC... --label "Payroll v2" --warn-ledgers 518400
sentinel registry remove --target CC...

Writes are signed with SENTINEL_SECRET; --owner defaults to the signing account.

Environment

VariablePurpose
SENTINEL_NETWORKDefault network
SENTINEL_RPC_URLDefault RPC endpoint
SENTINEL_REGISTRY_IDDefault registry contract id
SENTINEL_SECRETSigning key for registry writes
SENTINEL_PUBLIC_KEYRead-only source account (required on mainnet)
SENTINEL_WARN_LEDGERSDefault warn window

On testnet and futurenet, read-only commands with no key generate a throwaway account and fund it via friendbot, purely so RPC simulation has a source account.

Config file

{
  "network": "testnet",
  "registry": "CC4TQFW5GLQTOKWTDE7IJWPQFWJ4NWVMJGBFWB76PUP3T7CEOVVSQW6O",
  "contracts": [
    { "contract": "CDLZFC3SYJYD...", "label": "XLM SAC", "warnLedgers": 518400 }
  ]
}

deployments.json is this file, so the CLI works with no flags in a fresh clone.

SDK

packages/sdk exports the same primitives the CLI uses: projectTtl, classifyRisk, instanceLedgerKey, scanTargets, readWatchlist. Pure functions are dependency-free and tested without a network.
